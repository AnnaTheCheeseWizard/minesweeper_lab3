# Сапер із розв'язувачем (Android, Kotlin)

Лабораторна робота 3. **Власний варіант завдання:** гра «Сапер» з вбудованим алгоритмом-розв'язувачем (solver),
який вміє підказувати ходи, робити крок і проходити гру автоматично.
> Згідно з умовою лабораторної, власний варіант потрібно погодити з викладачем.

## Відповідність вимогам

| Вимога | Реалізація |
|---|---|
| Kotlin/Java | Kotlin 2.0, Android Views (без Compose) |
| Віддалений репозиторій, логічні коміти, `.gitignore` | Історія в `git log`; `.gitignore` виключає `build/`, `.gradle/`, `local.properties`, `.idea/`, ключі підпису, `*.apk` тощо |
| Логування через правильно налаштований Logger | **Timber** (`util/AppLogger.kt`): у debug — усі повідомлення з тегом `Клас:рядок`; у release — лише WARN/ERROR зі stack trace |
| i18n | English (за замовчуванням), Українська, עברית (іврит, RTL); `plurals` (укр. має форми one/few/many/other, іврит — one/two/other), форматні рядки з позиційними аргументами; **перемикання мови всередині застосунку** (`AppCompatDelegate.setApplicationLocales`) + `locales_config.xml` для системних налаштувань «Мова застосунку» (Android 13+) |

## Як грати

* дотик по закритій клітинці — відкрити;
* довге натискання — поставити/зняти прапорець;
* дотик по відкритому числу — «chord» (відкрити сусідів, якщо кількість прапорців збігається з числом);
* перший хід завжди безпечний;
* меню ⋮: нова гра, складність (Новачок 9×9/10, Середній 16×16/40, Експерт 16×30/99), мова;
* кнопки solver-а: **Підказка** (підсвічує клітинки: зелена — безпечна, червона — міна, жовта — ризикований здогад),
  **Крок** (виконує один пакет ходів), **Авто** (грає сам, кнопка перетворюється на «Стоп»).

## Алгоритм solver-а

Solver працює **лише з тим, що бачить гравець** (`BoardSnapshot`), тобто не «підглядає» за мінами.
Прапорці гравця ігноруються (вони можуть бути хибними). Техніки застосовуються від простих до складних,
повертаються ходи першої, що спрацювала:

1. **Просте правило** – число `N` має рівно `N` закритих сусідів → усі міни; `N = 0` → усі безпечні.
2. **Правило підмножин** – якщо закриті сусіди числа A є підмножиною сусідів числа B, то різниця
   визначається значенням `B − A` (так розв'язується, наприклад, шаблон 1‑2‑1).
3. **Точний перебір (CSP)**
   * *frontier* — закриті клітинки, що межують із числами; вони розбиваються на незалежні компоненти;
   * для кожної компоненти бектрекінгом перебираються **усі** узгоджені розташування мін
     (з відсіканням за обмеженнями; ліміт 300 000 вузлів на компоненту);
   * компоненти поєднуються з **глобальним лічильником мін** (`BigInteger`, бо числа комбінацій величезні):
     вага розташування = ∏ кількостей × C(клітинок поза frontier, решта мін);
   * отримуємо **точну ймовірність міни** для кожної клітинки; 0 → безпечна, 1 → міна.
4. **Здогад** – якщо певних ходів немає, обирається клітинка з найменшою ймовірністю міни
   (при рівності — з більшим шансом відкрити «нуль», що віддає перевагу кутам і краям).
   Якщо компонента завелика для перебору, використовується евристична оцінка.

Складність у гіршому випадку експоненційна за розміром компоненти frontier, але на практиці
frontier-компоненти малі, а відсікання працює ефективно.

### Орієнтовна ефективність

Проходження повністю автоматичним solver-ом (перевірено на еталонній реалізації алгоритму):

| Складність | Перемоги |
|---|---|
| Новачок | ≈ 96 % |
| Середній | ≈ 83–88 % |
| Експерт | ≈ 50 % |

Частину партій неможливо виграти без здогаду (позиції, де всі ходи ризиковані), тому 100 % недосяжні.

## Логування

```kotlin
Timber.d("Tap at (%d, %d), changed=%b", row, col, changed)   // налагодження
Timber.i("New game: %s", difficulty)                          // події
Timber.w("Solver: component of %d cells exceeded the node budget", n)
```

* `MinesweeperApp.onCreate` викликає `AppLogger.init(BuildConfig.DEBUG)`.
* **debug** → `LineNumberDebugTree` (тег `MainActivity:128`, клікабельний у Logcat);
* **release** → `ReleaseTree`, що пропускає лише `WARN`+ (сюди ж можна підключити Crashlytics).
* Логер використовується і в чистій логіці (`Board`, `MinesweeperSolver`); у юніт-тестах дерев немає, тому виклики нічого не роблять.

Фільтр у Logcat: `package:mine level:debug`.

## Інтернаціоналізація

* `values/strings.xml` — English (за замовчуванням), `values-uk`, `values-iw` (іврит; папка `iw` — застарілий код мови, який вимагає Android lint).
* Усі тексти UI — у ресурсах; числа вставляються через форматні рядки (`%1$d`), множина — через `plurals`.
* Назви мов (`English`, `Українська`, `עברית`) не перекладаються, щоб користувач завжди міг їх знайти.
* Вибір мови: меню ⋮ → *Мова*. Збереження вибору забезпечує AppCompat
  (`AppLocalesMetadataHolderService` у маніфесті для Android ≤ 12, системні налаштування для Android 13+).
* Іврит — мова з письмом справа наліво: `android:supportsRtl="true"` у маніфесті віддзеркалює інтерфейс автоматично
  (рядок стану, кнопки), а саме поле гри малюється однаково в усіх мовах. У `locales_config.xml` і `LanguageManager` використовується тег `he`.
* Щоб додати мову: створити `values-xx/strings.xml`, додати `<locale>` у `xml/locales_config.xml`
  та пункт у `LanguageManager.options`.

## Збірка та запуск

Потрібно: **Android Studio** (Ladybug або новіша), JDK 17, Android SDK 35.

1. `File → Open…` і вибрати цю теку. Android Studio завантажить Gradle 8.9 згідно з
   `gradle/wrapper/gradle-wrapper.properties` і синхронізує проєкт.
   (Файли `gradlew`/`gradle-wrapper.jar` у репозиторій не входять — за потреби згенеруйте командою
   `gradle wrapper` або через *Tools → Gradle*.)
2. Запустити конфігурацію **app** на емуляторі/пристрої (Android 8.0+, API 26).
3. Юніт-тести: `./gradlew test` або ПКМ на `app/src/test` → *Run Tests*.

Версії бібліотек (AGP, Kotlin, Material) можна підняти — Android Studio запропонує оновлення.
`applicationId` / `namespace` (`com.example.minesweeper`) змініть на власні перед публікацією.

## Тести

* `BoardTest` — безпечний перший хід, кількість мін, flood fill, прапорці, chord, перемога/поразка, прихованість мін у знімку.
* `MinesweeperSolverTest`
  * ручні шаблони: просте правило, 1‑2‑1, глобальний лічильник мін, здогад із найменшим ризиком;
  * **перевірка коректності**: на 150 випадкових партіях жодний «певний» хід solver-а не суперечить реальному розташуванню мін;
  * частка перемог: Новачок ≥ 85 %, Середній ≥ 65 %.
